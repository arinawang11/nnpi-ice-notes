# 故障排查笔记

## CPU 频率固定在 500 MHz

卡端 CPU 的 HWP 状态被硬件信号压制（PROCHOT、VR Therm、TurboRatioLimit），
不是功率或温度策略导致。写入 PL1/PL2 或 PM_ENABLE 无效，部分寄存器写后
被锁定。软件层无法提升频率。

## 读取 MSR

卡端没有 `msr-tools`，直接按字节偏移读 `/dev/cpu/0/msr`：

```sh
dd if=/dev/cpu/0/msr iflag=skip_bytes bs=8 skip=<msr> count=1 2>/dev/null
```

文件偏移等于 MSR 编号，不是编号乘以 8。使用 `skip_bytes` 而不是 `skip`，
后者以块为单位，会读到错误位置并产生 `EIO`，容易误判为内核拦截。

## x11vnc 握手卡死

两个独立原因：

1. 启动时加了 `-v`：详细日志触发内核 socket 忙循环，RFB 握手无响应。
2. 启动顺序错误：先起了 twm/xterm 再起 x11vnc，进程卡在 `poll`。

解决：去掉 `-v`，并把 x11vnc 放在窗口管理器之前启动。

## Xvfb 连接被拒绝

Xvfb 未加 `-ac` 时，访问控制会阻塞客户端，表现为连接挂起。始终使用：

```sh
Xvfb :0 -ac -screen 0 1024x768x24
```

## WSL 中看不到 Windows 盘符

部分精简 WSL 发行版没有自动挂载。手动挂载：

```sh
mount -t drvfs C: /mnt/c
```

挂载后再执行跨文件系统的复制。构建目录建议放在 ext4 虚拟盘上，不要直接
在 `/mnt/c` 下编译。

## MMIO 读回全 0xFFFFFFFF

可能原因按优先级排列：

1. ICE 未上电：窗口整体不可访问。确认 power-enable 位与 ready 轮询。
2. 读了未实现的 CBB 区域：该区域本就返回全 1。
3. 读取顺序污染：连续整页读未映射区域后，同进程后续的窗口读会返回全 1，
   即使目标区域已实现。单次读未映射地址不会立即触发。
4. 设备确实无响应：需要用 HUB 健康寄存器在前后做差分，排除前三种。

排查时先读已实现区域（DELPHI/HUB），再读未实现区域（TLC），并在关键读
前后各读一次健康寄存器。

## 全 0 读回

全 0 不等于硬件健康。未初始化的状态字、未加载的固件、被门控的子系统都
可能读 0。只有在确认电源、时钟和固件状态后，0 才有诊断意义。

## 设备在热插拔或重载后不再就绪

卡端固件可能停在“已启动过一次”的状态，doorbell 不再向就绪推进。需要让
卡端完成一次干净的电源周期，而不是在残留状态上重复提交。主机重启可以
提供这个周期；仅重装驱动通常不够。

## PCI 设备状态异常

检查命令寄存器是否仍启用 MEM 访问：

```sh
setpci -s <bdf> COMMAND
```

正常情况下应为仅 MEM（`0x0002`）或 MEM+IO。实验结束后恢复为 `0x0000`
可以避免设备在无驱动时响应 MMIO。恢复前确认没有 DMA 仍在使用缓冲区。
