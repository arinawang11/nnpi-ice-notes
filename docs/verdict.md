# 逆向可行性判定

## 结论

现有证据不支持“硬件已损坏”，也不支持“自研执行链已闭合”。主机通信、
ICE 上电、DELPHI 配置面已验证；MAC 阵列、全部 ICE、真实地址翻译和真实
算术没有验证。这些层次不能合并为整卡健康证明。

- 修复到可引导、SSH 可访问、诊断可用：已完成。
- 自研首个真实算子：有架构依据，但仍是未闭合的研究任务。
- 恢复原厂全部推理功能：现有资料不足，无法给出可验证的工期或成功率。

## 依据

驱动源码与寄存器接口的复核表明：

- TLC 通过 APB remote configuration 向 DELPHI 下发配置，`MS_CFG` 的
  mode 0 旁路的是配置状态机，不承诺旁路 LSU credit，也不等于 CPU MMIO
  可以完整替代 TLC 职责。
- 输入 IRAM/BRAM 的 SP 不等 credit 位只适用于 SP；ORAM 对应位明确为
  always zero / not applicable。不能推导“全链路无 credit”，也不能推导
  每种输出模式都需要外部 credit。
- GEMM streaming 的定义没有解除 credit 协议。
- 自研候选路径选择 system memory 与 A/B/C streaming，不是已验证的
  SP bypass 路径，也没有 `MS_CFG` 配置项。历史超时不能证明所有无固件
  直配路线都不可行。

## 历史实验的可信度

历史实验存在明确的软件错误：AXI enable 错位、回读豁免、输出只验首行、
页表模式前提缺失。这些错误足以使历史超时不能作为“计算阵列损坏”的证据，
但也不能证明修正后一定成功。

较可靠的现场证据是：ICE0 的 PE/RDY 稳定，MMU、流路由、页码和属性字段
可完整读取。这不是 MAC 计算验证；没有新的真实 START 或输出，就不能
报告计算健康。

## 工程判断

继续增加只读诊断版本或反复搜索同一批资料，不会降低不确定性。真正有
价值的输入是：

1. 版本匹配的完整已知正确算子配置，以及原始输入/输出与 state/credit
   时序；
2. 可分析的 TLC 或用户态初始化实现，或足够完整的编程规范；
3. 在明确接受风险的前提下，用有具体范围的受控实机实验检验假设。

第 3 项需要可执行的风险控制方案，且不能取消不盲写、页面所有权明确、
保存现场和不复位重试的约束。已部署的固定禁用版本不应改成试错工具；
一次常量冒烟成功也不能外推为全功能恢复。
